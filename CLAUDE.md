# CLAUDE.md — Raw Motion Frame

Сайт студии видеомонтажа **Raw Motion Frame**: показываем услуги и портфолио (видео), принимаем заявки на консультацию. Главная цель: клиент быстро находит нас и оставляет заявку.

Язык общения и комментариев в коде: русский. Названия переменных, файлов, компонентов: английский. Сайт только на русском (i18n не добавлять).

## Стек

- Vue 3 (Composition API, `<script setup lang="ts">`)
- Vite + TypeScript (strict)
- Vue Router 4 (history mode)
- Pinia только если нужно общее состояние (например, открытие модалки заявки)
- GSAP + ScrollTrigger для анимаций
- vite-ssg: пререндер страниц (это SPA, но поисковики получают готовый HTML)
- `@unhead/vue` для title, description и Open Graph
- Стили: обычный CSS с переменными, без тяжёлых UI-фреймворков
- PrimeVue **4.x** (MIT) только для полей формы и галочек (`InputText`, `Textarea`, `Checkbox`). Тема Aura, перекрашенная в фирменные цвета: `src/theme/primevue.ts`. PrimeVue 5.x и `@primeuix/themes` 3.x идут под коммерческой лицензией PrimeUI (нужен ключ, без него на сайте плашка), поэтому не обновлять без решения владельца
- Иконки: `lucide-vue-next`. Иконку Instagram в подвале оставить инлайн SVG
- Хостинг: **Vercel**. Заявки идут в Telegram-бот через Vercel Function `api/lead.ts`
- Аналитику и трекеры **не подключаем** (ни Метрику, ни GA), поэтому cookie-баннер не нужен

Новые библиотеки без необходимости не добавлять. Если нужна зависимость, сначала объясни зачем.

## Дизайн (по брендбуку)

Источник фирменного стиля — брендбук «Logo presentation» (`Logo presentation@2x.png`, слоган **Visuals that move**), а не рекламный ролик (в ролике синяя палитра, на сайте она не используется). Токены в `src/assets/styles/main.css`.

Палитра (точные значения из брендбука):

| Роль | Цвет | Где |
|---|---|---|
| Primary | `#0A0A0A` | тёмные блоки, текст на светлом и на лайме |
| Secondary | `#F2F0EA` | светлые блоки, текст на тёмном |
| Accent | `#C6FF00` | кнопки, плашка под ключевым словом, плейхед, фокус |
| «Призрачная» полоса | `#504F4D` | декор (полоса движения в символе), границы полей |

- Серые `#222220`, `#504F4D`, `#757570` только для декора и линий, не как цвет текста. Приглушённый текст: `#B4B3AB` на тёмном, `#56554F` на светлом.
- Лайм дозированно: одно акцентное место на экран. На лайме текст только чёрный. Без свечений и неоновых эффектов.

Логотип:

- Основной: символ + «RAW MOTION» + «FRAME» в рамке + слоган «Visuals that move». На сайте: `logo.png` в шапке (без слогана, на высоте 40 px он не читается), `logo-full.png` в подвале.
- Символ: два уголка видоискателя, серая «призрачная» полоса (движение) и лаймовая полоса (плейхед). Символ — фавиконы и аватар.
- В брендбуке есть светлая и чёрно-белая версии. Пока на сайте только PNG-вырезки на тёмном фоне: шапка поэтому со сплошным фоном `#0A0A0A`.
- Использовать как есть, без искажений, с отступом. Не перерисовывать. Нужен SVG от дизайнера (см. ниже).

Композиция (по образцу phenomenonstudio.com: берём подачу, не цвета и не тексты):

- Чередование тёмных и светлых блоков. Тёмные блоки (Hero, «Услуги», форма с подвалом) со скруглёнными краями наезжают на светлый фон `#F2F0EA`.
- Скругления: блоки 28–40 px, карточки 16 px, кнопки и поля 10 px.
- Огромные заголовки слева, сетки с тонкими линиями, карточки работ и цен на `#E7E5DE`.

Типографика и тексты:

- Inter (кириллица), заголовки 600, плотный трекинг (-0.035em). Не 800/900.
- **Не использовать** мелкие подписи капсом над заголовками секций и кнопки капсом: владелец считает это «похожим на ИИ». Капс с разрядкой только внутри самого логотипа.
- Заголовки простые и живые («Услуги», «Наши работы», «Как проходит заказ», «Цены»), без маркетинговых фраз.

Фирменные мотивы:

- уголки-видоискатель (шоурил в Hero, hover на карточках работ, заглушки видео);
- лаймовая плашка под одним ключевым словом (только в Hero);
- серая + лаймовая горизонтальные полосы из символа (анимация плейхеда);
- таймлайн монтажа / плейхед (полоса над этапами заказа).

Мобильная версия в приоритете: аудитория приходит из соцсетей. Сначала вёрстка под 375 px, потом десктоп.

## Анимации

Анимаций много, но они не должны ломать скорость и доступность.

- Всё на GSAP. `ScrollTrigger` регистрировать один раз.
- Создавать в `onMounted` внутри `gsap.context()`, убирать в `onUnmounted` через `ctx.revert()`. Иначе будут утечки и дубли.
- Идеи:
  - Hero: заголовок по словам, плашка выезжает, уголки шоурила раскрываются, лаймовая полоса-плейхед вытягивается;
  - заголовки по словам/буквам (кинетическая типографика);
  - счётчик «100+» с count-up при появлении;
  - плейхед над этапами «Как проходит заказ» (scrub);
  - карточки работ: появление каскадом, hover с лаймовой рамкой-видоискателем;
  - бегущая строка с услугами;
  - карусель партнёров (см. ниже);
  - переходы между страницами (`<Transition>` + GSAP);
  - микроанимации кнопок, полей формы, успешной отправки.
- Анимируем только `transform` и `opacity`.
- Уважать `prefers-reduced-motion` (`gsap.matchMedia()`): тяжёлые анимации отключать.
- Во время пререндера нет `window`. Весь код с `window`, `document`, `ScrollTrigger` только в `onMounted` или под `import.meta.env.SSR`.

## Партнёры (карусель)

Блок «С нами сотрудничают». Данные в `src/data/partners.ts`:

| Партнёр | Сайт | Логотип |
|---|---|---|
| Findy Job | https://findy-job.com | `public/partners/findy-job.svg` |
| Siteless | https://geoapify-bot.vercel.app/ | `public/partners/siteless.svg` |

- Логотипы бесконечно едут лентой (marquee на CSS или GSAP). Список дублируется для бесшовной петли, дубликаты с `aria-hidden="true"`.
- Пауза при наведении и при `prefers-reduced-motion` (тогда статичный ряд).
- Каждый логотип ссылка на сайт партнёра: `target="_blank" rel="noopener noreferrer"`, `alt` с названием.
- Логотипы приводим к единому виду (одна высота, монохром или цветные, но в одной логике).
- Пока файлов логотипов нет, показываем текстовый вордмарк-заглушку. Не скачивать и не перерисовывать чужие логотипы самовольно: файлы даёт владелец сайта.
- Партнёров будет больше, поэтому компонент работает от массива.

## Портфолио и видео

- В тексте указываем «100+ смонтированных роликов». Других цифр и клиентов не выдумывать.
- Карточки: короткое превью без звука (`muted playsinline loop`), полное видео по клику (модалка).
- У каждого видео `poster`. Превью лениво грузятся (`preload="none"` или `metadata`).
- Автоплей только в зоне видимости (IntersectionObserver), не больше 1–2 видео одновременно.
- Превью сжимать заранее (до ~2–3 МБ), форматы mp4/webm. Тяжёлые файлы не класть в репозиторий без нужды.
- Реальные ролики даёт владелец. До этого используем заглушки с понятным названием файла.
- Рекламный ролик студии (вертикальный 1080×1920) можно показать в Hero или портфолио как пример.

## Форма заявки

Поля:

1. **Имя** (обязательно)
2. **Компания** (обязательно): «Название компании или «частное лицо»»
3. **Контакты** (обязательно): телефон, Telegram или Instagram. Подсказка с примером формата.
4. **Описание задачи** (необязательно)
5. Согласие на обработку данных со ссылкой на `/privacy` (обязательно)

Правила:

- Валидация на клиенте (сообщения на русском) и повторно на сервере.
- Состояния: idle, loading, success, error. Кнопка блокируется при отправке.
- Защита от спама: honeypot-поле, минимальное время заполнения, проверка длины и формата на сервере. Простой счётчик в памяти на serverless ненадёжен, поэтому при необходимости использовать Vercel Firewall / rate limiting.
- Анимированное сообщение об успехе.
- Сообщение в Telegram: имя, компания, контакты, описание, время.
- **Токен бота никогда не попадает во фронтенд.** Фронт делает `POST /api/lead`. Функция `api/lead.ts` читает `TELEGRAM_BOT_TOKEN` и `TELEGRAM_CHAT_ID` из переменных окружения Vercel.
- В репозитории только `.env.example` без реальных значений. `.env` в `.gitignore`.

## Доступность

- Контраст по WCAG AA (лайм на чёрном проходит; серые полоски не использовать как носитель текста).
- Всё доступно с клавиатуры, видимый `:focus-visible`.
- У видео есть управление и кнопка паузы анимации.
- Форма: `label` у каждого поля, ошибки через `aria-describedby`.

## Правила кода

- Компоненты на `<script setup lang="ts">`, PascalCase, один компонент на файл.
- Props и emits типизировать. Без `any`.
- Логику выносить в composables, компоненты небольшие.
- Общие анимации в `components/animations` и `composables`, без дублирования.
- Минимум комментариев: только там, где неочевидно «почему».
- Не менять рабочее без причины и не делать рефакторинг «заодно».
